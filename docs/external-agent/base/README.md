# Canonical external web-agent portfolio context

External-context version: `2026-08-02.5`

This README is a local installation manifest. Do not upload it. The persistent
provider context is deliberately separate from the local Codex workflow.

## Exact persistent set

Install the complete contents of `PROJECT_INSTRUCTIONS.txt` in the provider's
project-instructions field. Install exactly these four knowledge files once
each:

1. `01-AUDIENCE-AND-PORTFOLIO-GOAL.md`
2. `02-STORY-AND-READER-STANDARD.md`
3. `03-EVIDENCE-AND-ACCURACY-STANDARD.md`
4. `05-MASON-WRITING-VOICE.md`

Do not install `04-EXTERNAL-AGENT-PACKET-GUIDE.md`. It is the local sender and
QA runbook. Do not upload this README, repository instructions, local skills,
test fixtures, validation output, or internal planning material.

`PROJECT_INSTRUCTIONS.txt` contains the compact provider-neutral behavior. The
numbered files add stable context: 01 owns audience and hiring value; 02 owns
story and prose quality; 03 owns evidence and accuracy; and 05 owns Mason's
Portfolio voice. The voice samples guide style only and never supply case facts,
claims, structure, or conclusions.

## Current-chat context

Mason's ordinary-language request and the material supplied in the current chat
define the task and authorization. Add only the relevant draft, facts,
screenshots, artifacts, and constraints. A formal packet is never required.

Because the persistent project contains 05, it is a voice-aware Portfolio
collaboration context. It is not an independent blind-reader or factual-
validator context. Run either independent check in a fresh projectless context
without 05, the project instructions, prior feedback, or local rationale.

A local repository change does not update a provider. Provider synchronization
requires separate authorization. Keep `PROJECT_INSTRUCTIONS.txt` below 8,000
Unicode characters.

## Keep the context selective

Do not upload raw conversation exports, private archives, test files, source
ledgers, or every available screenshot. They add noise and encourage the agent
to obey old decisions instead of finding the strongest story.

Supply the relationships that matter: company or team pressure, the relevant
initiative, Mason's role and decisions, candidate artifacts, and the strongest
supported ending. A story-library extract may contain several related items
when the task is to discover which combination makes the most complete case.

## Useful challenge without local orchestration

An outside model should challenge existing case pages, drafts, titles, evidence
selections, and layouts when the request calls for it. It should not ignore
known facts or Mason's explicit corrections. Rejected work is included only
when the task is to diagnose it and must be labelled as rejected rather than
presented as a target.

Do not reproduce local skills, roles, review sequences, routing rules, model
choices, browser procedures, or repository mechanics in the persistent context
or current-chat instructions.
